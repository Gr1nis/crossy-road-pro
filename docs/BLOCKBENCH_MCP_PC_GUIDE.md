# 🛠️ Руководство по настройке Blockbench MCP и Мастер-Промпт для ПК (Crossy Road Pro)

> **Назначение документа**: Этот файл содержит полное руководство по подключению **Blockbench MCP** к Antigravity на ПК (Windows / Linux / macOS) и **Мастер-Промпт (Master Prompt)**, кодирующий все стандарты 3D-моделирования, правила воксельной сетки, устранение Z-файтинга, запуск сабагентов-критиков и пайплайн бесшовной интеграции моделей в проект Crossy Road Pro.

---

# ЧАСТЬ 1. Инструкция по настройке Blockbench MCP на ПК

### Шаг 1. Предварительные требования на ПК
1. Установлен **Node.js 18+** (проверить в терминале: `node -v`).
2. Установлен настольный редактор **Blockbench 4.8+** (скачать с [blockbench.net](https://www.blockbench.net/)).
3. Установлен **Git** (`git -v`).

---

### Шаг 2. Клонирование и сборка сервера `blockbench-mcp`
Откройте терминал (PowerShell или Git Bash на Windows) и выполните:
```bash
# Клонируем репозиторий сервера в удобную папку (например, в домашнюю директорию или tools)
git clone https://github.com/sosadly/blockbench-mcp.git
cd blockbench-mcp

# Устанавливаем зависимости и компилируем TypeScript
npm install
npm run build
```
После сборки в папке `blockbench-mcp/dist/` появится файл `index.js`.
Запомните абсолютный путь к `dist/index.js` (например, на Windows: `C:\Users\<ВашеИмя>\blockbench-mcp\dist\index.js` или `C:/Users/<ВашеИмя>/blockbench-mcp/dist/index.js`).

---

### Шаг 3. Установка плагина-моста в Blockbench
Сервер MCP общается с запущенным Blockbench через локальный плагин:
1. Запустите настольное приложение **Blockbench**.
2. В верхнем меню выберите: **Файл (File) ▸ Плагины... (Plugins...)**.
3. В окне плагинов нажмите **Загрузить из файла (Load Plugin from File)** (иконка папки вверху).
4. Перейдите в папку склонированного репозитория: `blockbench-mcp/plugin/` и выберите файл **`blockbench_mcp.js`**.
5. При появлении запроса подтвердите разрешение на локальный сетевой доступ (Allow network access).
6. В интерфейсе Blockbench появится боковая панель **MCP Copilot**, а в верхнем меню появится пункт **Инструменты ▸ Start MCP Server**.

> [!IMPORTANT]
> Мост работает на локальном порту **`http://127.0.0.1:8787`**. Каждый раз при начале сессии моделирования Blockbench должен быть открыт, а сервер запущен (кнопка *Start* в панели MCP Copilot или пункт меню `Tools ▸ Start MCP Server`).

---

### Шаг 4. Настройка конфигурации MCP в Antigravity на ПК
В вашей домашней папке на ПК найдите (или создайте) конфигурационный файл MCP Antigravity:
* **Путь к конфигу на ПК**:
  * Windows: `%USERPROFILE%\.gemini\config\mcp_config.json` (или в настройках Antigravity IDE: Settings ▸ MCP Servers).
  * macOS: `~/.gemini/config/mcp_config.json`.
  * Linux: `~/.gemini/config/mcp_config.json`.

Добавьте секцию `"blockbench"` в `mcpServers`:

#### Пример для Windows:
```json
{
  "mcpServers": {
    "blockbench": {
      "command": "node",
      "args": [
        "C:/Users/<ВашеИмя>/blockbench-mcp/dist/index.js"
      ],
      "disabled": false
    }
  }
}
```
*(Используйте прямые слеши `/` или экранированные двойные обратные слеши `\\\\` в путях).*

---

### Шаг 5. Проверка соединения
В чате с Antigravity на ПК выполните проверку:
1. Запустите Blockbench и нажмите **Start MCP Server** (должно загореться зеленым: `Running on port 8787`).
2. В Antigravity вызовите инструмент `get_status` (или попросите агента проверить статус подключения Blockbench).
3. Должен прийти ответ: `{"status": "ok", "version": "...", "model_open": ...}`.

## 1. СТРОГИЕ ПРАВИЛА ВОКСЕЛЬНОЙ СЕТКИ (docs/VOXEL_GRID_SPECIFICATION.md)
- Базовый квант сетки: `VOXEL_UNIT = 0.05` единиц Three.js.
- 1 игровая полоса (Lane) = 1.0 единица = ровно 20 вокселей сетки.
- Контакт с землей: нижняя грань лап/колес/подошв должна быть строго на Y = 0.00.
- Бюджеты кубов (строго соблюдать):
  * Фоновые пропсы: 15–35 кубов.
  * Персонажи: 40–70 кубов (модели должны быть выразительными, но оптимизированными).
  * Транспорт: 80–150 кубов.
  * Здания-таунхаусы: 100–180 кубов.

## 2. АНАТОМИЧЕСКИЕ И ВИЗУАЛЬНЫЕ ЗАКОНЫ
1. Монолитная сердцевина (Solid Core):
   Внутреннее ядро туловища должно быть 100% сплошным. Никаких «дыр» и щелей, сквозь которые видно фон при вращении модели в изометрии.
2. Никаких левитирующих элементов:
   Лапы, аксессуары, хвосты, наушники должны иметь физически правдоподобное основание и крепление к телу.
3. Читаемость и контраст:
   - Глаза должны четко считываться с любого ракурса (разделение на лбу, темные зрачки, светлые блики).
   - Аксессуары не должны сливаться с телом или закрывать глаза (короны, шапки, очки располагаются с зазором или четким силуэтом).
   - Хвосты крепятся к телу под анатомическим углом, а не «растут из плаща».

## 3. СТРОГИЙ ЗАПРЕТ НА Z-FIGHTING (COPLANAR OVERLAPS = 0)
- Любое совпадение параллельных граней в одной координатной плоскости (копланарное наложение) — КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО (`coplanar_overlap = 0`).
- Смежные детали стыкуются ровно граница к границе либо выступают наружу ступенчато (+0.02..0.05).
- Перед утверждением модели ВСЕГДА запускается автоматический скрипт проверки на пересечение граней (`blockbench_coplanar_check.py`).

## 4. КООРДИНАТНЫЙ МОСТ: BLOCKBENCH ⟷ THREE.JS
Blockbench ориентирован лицом на -Z (North), правая сторона модели = +X (East).
Three.js в Crossy Road Pro ориентирован лицом на +Z.
Формулы пересчёта:
- Ширина:  w = (tx - fx) * 0.05
- Высота:  h = (ty - fy) * 0.05
- Глубина: d = (tz - fz) * 0.05
- Центр X: x = ((fx + tx) / 2) * 0.05
- Центр Y: y = ((fy + ty) / 2) * 0.05
- Центр Z: z = -((fz + tz) / 2) * 0.05  (минус разворачивает модель лицом вперед!)

## 5. АВТОНОМНЫЙ ПАЙПЛАЙН РАЗРАБОТКИ СУБАГЕНТАМИ (GAME CRITICS)
При моделировании каждого персонажа соблюдается единый 5-этапный цикл:
1. Блок-аут и детализация: Создание `.bbmodel` через MCP или процедурный генератор по ТЗ из `docs/CHARACTER_PACKS_SPECIFICATION.md`.
2. Математический аудит: Проверка отсутствия копланарных граней (`coplanar_overlap = 0`) и контакта с землей ($Y = 0.00$).
3. Рендеринг 5 ракурсов: Изометрия 3/4, Спереди, Справа, Сзади, Сверху.
4. Вызов независимого сабагента-критика (`invoke_subagent` с ролью "Asset & Voxel Critic"):
   Критик слепо инспектирует силуэт, анатомию, читаемость глаз, пропорции и отсутствие артефактов.
5. Презентация пользователю: Демонстрация рендера, вердикт критика, внесение правок по замечаниям до идеального результата (10/10).

## 6. ПОЛНАЯ ИНТЕГРАЦИЯ В ИГРУ (КОДОВАЯ БАЗА)
После утверждения модели агент автоматически:
