# 🏙️ Ремастер Мира 1 («Городские легенды»): Архитектурный регламент и пайплайн работы

> **Назначение документа**: Данный регламент предназначен для автономной работы ИИ-агентов в новом чате. Он фиксирует все стандарты качества, спецификации воксельной сетки, роли субагентов и строгий двухагентный цикл приёмки моделей («Архитектор ↔ Критик») с порогом 10/10 перед показом пользователю.

---

## 1. Архитектурные инварианты проекта Crossy Road Pro

1. **Core / View Wall**:
   - `src/core/` (чистая физика, полосы, генератор, логика столкновений) **никогда** не импортирует Three.js, DOM или WebAudio.
   - Любое визуальное представление находится строго в `src/view/` или `src/app/`.
2. **Лимит длины файлов**:
   - **Строго $\le 300$ строк** на файл. При приближении к лимиту модуль делится (например, `urbanVehicles.ts` и `urbanVehiclesExpansion.ts`).
3. **Zero Runtime Allocations**:
   - Внутри циклов анимации (`animate()`, `sync()`) запрещено аллоцировать память (`new THREE.Vector3()`, `new THREE.Color()`, `new Set()`). Все векторы и цвета кэшируются как поля классов.
4. **Очистка ресурсов (Memory Leak Prevention)**:
   - При удалении любых мешей из сцены (или пулинге) обязательно вызывается рекурсивный `dispose()` для геометрий и материалов (`VoxelPalette`).
5. **Quality Gates перед коммитом**:
   - `npx tsc --noEmit` — 0 ошибок.
   - `npm test` — все тесты проходят (`node --experimental-strip-types --test`).
   - `node scripts/build.mjs` — сборка `index.html` и бандла успешна.

## 2. Стандарты воксельной геометрии (VOXEL_GRID_SPECIFICATION)

- **Базовый шаг сетки**: `VOXEL_UNIT = 0.05` единиц Three.js.
  - $1.0$ игровая единица = ровно $20$ вокселей.
- **Целочисленная привязка**: все координаты и размеры кратны $0.05$. Дробные костыли (`+0.012`, `+0.005`) запрещены.
- **Zero Z-Fighting**: компланарные наложения граней строго запрещены (`coplanar_overlaps = 0`, валидация через `scripts/blockbench_coplanar_check.py`).
- **Заземление (Grounding)**: все элементы, контактирующие с землей (колеса машин, ножки скамеек, дно кадок, цоколи зданий), имеют нижнюю грань строго на $Y = 0.00$ ($min\_y = 0.00$).
- **Полая оболочка (Hollow Shell)**: моделируется только внешняя видимая форма; заполнение замкнутых внутренних объемов монолитным массивом запрещено.
- **Связность графа (Solid Core)**: модель представляет собой единый непрерывный граф, $0$ левитирующих вокселей.

## 4. Пайплайн разработки: Двухагентный цикл («Архитектор ↔ Критик»)

Работа над каждой моделью строится исключительно через автономных субагентов по замкнутому циклу с **порогом приёмки 10 / 10**:

```
[Пользователь]
     │
     ▼
[Агент-Координатор] ────► [Субагент: Voxel Sculptor & Model Architect]
                                │ (Blockbench MCP, порт 8787)
                                │ Создает модель, квантует 0.05, заземляет Y=0,
                                │ проверяет coplanar_overlap = 0, рендерит 5 ракурсов.
                                ▼
                         [Субагент: Asset & Voxel Critic]
                                │ Проводит строгий аудит по 8 критериям:
                                │ - Шаг 0.05 (VOXEL_UNIT)
                                │ - Grounding min_y = 0.00
                                │ - Попадание в бюджет кубов
                                │ - Zero Z-fighting (coplanar_overlap = 0)
                                │ - Solid Core (0 летающих вокселей)
                                │ - Hollow Shell
                                │ - Читаемость в изометрии 3/4
                                │ Выставляет оценку: X / 10.
                                │
               ┌────────────────┴───────────────┐
         Оценка < 10                      Оценка = 10 / 10 (Grade A+)
               │                                │
               ▼                                ▼
[Архитектор правит модель]             [Координатор формирует отчёт]
(замкнутый цикл исправления)                    │
                                                ▼
                                    [Презентация пользователю]
                                    (постер 2000x1220, 5 ракурсов)
```

### Регламент взаимодействия:
1. **Запуск Архитектора**: Координатор запускает субагента `Voxel Sculptor & Model Architect`, передавая ID модели, описание, бюджет и референс.
2. **Создание в Blockbench**: Архитектор через Blockbench MCP (`new_project`, `set_project_meta`, `add_groups`, `add_cubes`) или вспомогательный скрипт рассчитывает координаты, генерирует модель, сохраняет `assets/models/<model_id>.bbmodel` и `.json`, рендерит 5 канонических ракурсов и собирает постер `scripts/create_<model_id>_review.py`.
3. **Аудит Критика**: Запускается субагент `Asset & Voxel Critic`. Он оценивает модель по 10-балльной шкале.
   - **Если оценка $< 10$**: Критик выдает перечень дефектов с точными координатами. Архитектор исправляет модель. Процедура повторяется до достижения **10 / 10**.
4. **Отчёт пользователю**: Только после оценки **10 / 10** агент показывает пользователю коллаж и спрашивает одобрение.
5. **Интеграция в движок**:
   - После одобрения модель транслируется в TypeScript (`src/view/`).
   - Файлы строго $\le 300$ строк.
   - Запускаются `npx tsc --noEmit` и `npm test`.
