## 🛠️ Шаг 1: Подготовка и обработка ассетов (Python + WebP Base64)

1. **Генерация 3D-кнопок пользователем**:
   - Кнопка «ВЫБРАТЬ / ВЫБРАН» (3D казуальный стиль).
   - Круглый красный крестик закрытия `[X]`.
   - 3D-заголовок меню «SKINS / ПЕРСОНАЖИ».
   - Исходники складываются в папку (например, `Downloads/Icons Skins Menu/`).
2. **Скриптовая очистка фона без белых/серых ореолов (`scripts/process_skins_icons.py`)**:
   - Удалять не только белый фон, но и серую тень по цветовой насыщенности (Saturation):
     - Корпус кнопки: saturation > 0.18.
     - Серая тень/фон: saturation < 0.12 (делать полностью прозрачной).
   - Обрезать по bounding box и сохранить в `references/processed_icons/`:
     - `skins_title.webp` (~480×180 px max)
     - `skins_close_btn.webp` (~128×128 px max)
     - `skins_select_btn.webp` (~320×120 px max)
3. **Модуль Base64**:
   - Создать `src/view/skinsIconsBase64.ts` со строками `data:image/webp;base64,...`.
   - **КРИТИЧЕСКИ ВАЖНО:** добавить `'src/view/skinsIconsBase64.ts'` в массив `moduleOrder` в `scripts/build.mjs`! (Иначе в браузере выпадет `ReferenceError`).

## ⚠️ Шаг 2: Критические архитектурные уроки и грабли (НЕ ПОВТОРЯТЬ ОШИБОК!)

1. **Никаких плоских 2D SVG полигонов**:
   - В проекте **уже готовы** настоящие 3D воксельные изометрические рендеры высокого разрешения со 100% прозрачным фоном и тёплым светом Three.js Lambert.
   - Они лежат в `references/processed_icons/`:
     - `char_corgi.webp`
     - `char_pigeon_pizza.webp`
     - `char_box_cat.webp`
     - `char_raccoon_bandit.webp`
     - `char_capybara_zen.webp`
   - Их base64 уже экспортируется в `src/view/gachaSkinsBase64.ts` (`GACHA_CHARACTER_SKIN_BASE64`).
   - Использовать их напрямую в карточках: `<img src="${GACHA_CHARACTER_SKIN_BASE64[skinId]}" class="skin-card-char-img">`.
2. **Защита от «чёрных квадратов» (Прозрачность альфа-канала)**:
   - **Никогда не создавать вторичный `new THREE.WebGLRenderer` и не рендерить в `renderTarget` без `alpha: true`!** Вторичный рендерер очищает фон непрозрачным чёрным цветом и перезаписывает прозрачные картинки чёрными квадратами.
   - Стили силуэта закрытого скина:
     ```css
     .skin-card-silhouette .skin-card-char-img {
       filter: brightness(0) drop-shadow(0 0 10px var(--rarity-glow));
     }
     ```
     Поскольку фон картинок 100% прозрачен, `brightness(0)` делает чёрным **только сам воксельный силуэт персонажа** (ушки корги, пиццу голубя, створки коробки кота, хвост енота, мандарин капибары), оставляя фон прозрачным.
3. **Защита кэша Three.js (Предотвращение синего экрана)**:
   - Никогда не вызывать `mesh.geometry.dispose()` на персонажах. Геометрии в `VoxelPalette.geoCache` являются общими синглтонами. Их вызов уничтожает буферы Three.js и приводит к синему экрану.

## 🤖 Шаг 3: Поэтапное выполнение через субагентов

### Этап 1: UI & CSS Architecture Subagent
- Обновить верстку модального окна в `index.html` и `scripts/build.mjs`.
- Настроить стеклянную карточку, левую плашку монет, центральный 3D-заголовок, правую кнопку `[X]`.
- Сверстать адаптивную сетку из 5 карточек персонажей с крупным превью (размер контейнера ~100×100 px, персонаж заполняет 84% кадра).
- Добавить стили плашек редкости (Common, Rare, Epic, Legendary) и кнопок статуса («ВЫБРАН», «ВЫБРАТЬ», «🔒 В АВТОМАТЕ»).

### Этап 2: State Machine & Gameplay Logic Subagent
- Реализовать контроллер выбора персонажей в `src/app/` (или расширить `uiManager.ts` / `skinsModal`):
  - Получение открытых скинов из `engine.getUnlockedSkins()`.
  - Открытые скины: рендерятся в полном цвете, кликабельны, отображают кнопку «ВЫБРАТЬ» (или «ВЫБРАН»).
  - При клике: `engine.selectSkin(id)`, `sceneManager.updatePlayerSkin(id)`, `audio.playSkinVoice(id)`.
  - Закрытые скины: рендерятся интригующим 3D-силуэтом с неоновым контуром редкости, имя замаскировано (`??? [RARITY]`), клик предлагает перейти в автомат призов.
  - Защита ввода: закрытие по клику на крестик, по тачу (`touchend`), по клавише `Escape`. Метод `close()` всегда оборачивать в `try...finally`.

### Этап 3: Verification & Playability Subagent
- Прогон автоматических проверок:
  1. `node scripts/build.mjs` — сборка чистого дистрибутива `index.html`.
  2. `npx tsc --noEmit` — 0 ошибок типов.
  3. `npm test` — все тесты (189+) проходят на 100%.
  4. Проверка правила длины файлов: строго `<= 300 строк`.

### Этап 4: Independent `game-critics` Audit Subagent
- Запуск независимого сабагента аудита (`game-critics: Fidelity, Asset & UI Critic`).
- Просмотр скриншотов через `view_file`.
- Проверка симметрии шапки, отсутствия артефактов, чистоты силуэтов и удобства выбора скинов.
- Выставление итоговой оценки (цель — 10/10).
