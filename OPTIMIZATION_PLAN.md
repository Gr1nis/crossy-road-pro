# 🚀 Crossy Road Pro — План оптимизации для слабых телефонов

> ⚠️ **Напоминание агенту**: Когда пользователь начнёт работу над новым сеттингом и новыми 3D-моделями (триггеры: *"новый сеттинг"*, *"новые модели"*), обязательно напомнить о данном документе и закладывать эти принципы прямо в архитектуру новых ассетов!

---

## Главные виновники просадок FPS на мобильных устройствах

### 🔴 1. Критические (дают 50–70% прироста FPS)
* **Shadow map 2048×2048** (`src/view/sceneManager.ts`):
  Тяжёлый shadow pass убивает мобильный GPU. Снизить на мобилках до `512×512` или отключать тени на слабых устройствах.
* **Аллокация новых мешей в hot path смерти** (`spawnDeathFeathers`, `spawnRecordConfetti`):
  Вызовы `new THREE.BoxGeometry` и `new THREE.Mesh` создают до 30 новых объектов за кадр, провоцируя GC pauses.
  *Решение*: `ParticlePool` с фиксированным пулом 32–48 объектов.
* **`MeshLambertMaterial` на каждый прыжок** (`spawnHopPuff`):
  Создание новых материалов при каждом приземлении.
  *Решение*: Статический пул/кеш материалов по биому.
* **`antialias: true` на мобилках**:
  Высокий оверхед на мобильных экранах с высоким DPI.
  *Решение*: `antialias: false` для тач-устройств + ограничение `pixelRatio` до 1.5.

---

### 🟠 2. Архитектура под новый сеттинг (закладывать сразу при создании моделей!)
* **InstancedMesh вместо сотен независимых `THREE.Group`**:
  Если новый сеттинг процедурный/воксельный — деревья, камни, разметку и однотипные машинки рендерить через `THREE.InstancedMesh` (1 draw call вместо десятков).
* **Кеширование геометрий и материалов в `MeshFactory`**:
  Повторно использовать одинаковые базовые боксы/меши.
* **Адаптивный `QualityManager`**:
  Автоопределение типа устройства (`low`, `medium`, `high`) по `navigator.maxTouchPoints` / CPU cores:
  - Low: 0 ambient-частиц, тени выкл, `pixelRatio: 1.0`
  - Medium: 6 ambient-частиц, shadow map 512, `pixelRatio: 1.5`
  - High: 21 ambient-частица, shadow map 1024–2048, `pixelRatio: 2.0`
